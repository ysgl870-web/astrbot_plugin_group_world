# 🌌 群聊世界 · Group World

> **一个 QQ 群，一个地区；所有玩家，共同组成一个持续运行的世界。**

**群聊世界（Group World）** 是一个面向 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的多人群聊 RPG 插件。

它不是把几个小游戏简单堆在一起，而是以 **“群聊即世界”** 为核心设计：让每个 QQ 群拥有自己的地区、阵营与世界状态，同时通过跨群旅行、决斗、悬赏、世界 Boss、排行榜等系统，把不同群连接成一个长期运行的共享世界。

---

## ✨ 项目定位

群聊世界希望解决传统 QQ 群 RPG 常见的三个问题：

- **玩几天就结束**：通过角色成长、职业、装备、宠物、任务、声望与成就形成长期成长线。
- **不同群互相孤立**：通过全球玩家身份、跨群旅行、跨群决斗、世界 Boss 与悬赏建立世界级互动。
- **管理员配置困难**：将复杂运营功能放入 Web 管理中心，并支持本地内容与 YSGL 云端玩法结合。

最终形成：

```
                    🌐 群聊世界
                         │
        ┌────────────────┼────────────────┐
        │                │                │
      QQ 群 A          QQ 群 B          QQ 群 C
       地区              地区              地区
        │                │                │
      玩家              玩家              玩家
        └────────────────┼────────────────┘
                         │
              ⚔️ 决斗 · 🎯 悬赏 · 👹 Boss
                         │
                 🏆 共同的世界排行
```

# 🎮 核心玩法

## 👤 角色与成长

每位玩家拥有独立的游戏角色与持久化数据。

主要成长内容包括：

- 玩家身份与 UID
- 等级与经验
- 金币等经济资源
- 职业与转职
- 技能学习与装备
- 装备与强化
- 宠物
- 任务
- 成就
- 世界声望
- 排行榜

角色数据会持续保存，不需要每次进入群聊重新开始。

---

## 🌍 世界系统

群聊世界采用：

> **全局玩家 + 群聊地区**

的双层世界模型。

每个 QQ 群可以作为一个独立地区，并拥有自己的：

- 地区
- 阵营
- 天气
- 世界状态
- 地区危险程度

玩家则属于整个世界，而不是只属于某一个 QQ 群。

因此可以实现：

**A 群玩家 → 前往 B 群地区 → 探索 → 战斗 → 获得资源 → 返回自己的地区**

旅行还可以根据地区危险等级产生不同的费用与风险。

---

## 🧭 探索与资源

玩家可以通过探索获得世界资源。

玩法包括：

- 探索
- 深度探索
- 危险探索
- 钓鱼
- 挖矿
- 打工
- 怪物遭遇
- 区域材料宝箱
- 装备宝箱
- 特殊奖励

探索并不是单纯的“随机发金币”，而是与装备、材料、怪物掉落、合成和成长系统连接。

# 🎯 悬赏系统

悬赏是群聊世界的重要多人 PvP 玩法。

管理员或符合条件的玩家可以创建悬赏，并使用插件已有资源作为奖励。

奖励可以组合：

- 💰 金币
- 💎 钻石
- ⭐ 经验
- 🧱 材料
- 🎒 道具
- ⚔️ 装备
- ☁️ YSGL 云端商品

悬赏奖励采用托管思路：

```
发布悬赏
   ↓
奖励进入托管状态
   ↓
目标接受
   ↓
建立正式决斗
   ↓
真正击败目标
   ↓
结算奖励
```

因此不会因为“发布悬赏”就凭空产生奖励。

同时支持：

- 每日发布限制
- 同时进行中限制
- 金额上下限
- 发布费用
- 同目标冷却
- 目标拒绝
- 超时
- 取消与退款

# 👹 世界 Boss

世界 Boss 是整个群聊世界共同参与的大型活动。

与普通群 Boss 不同，世界 Boss 面向整个共享世界。

多个 QQ 群的玩家可以共同参与：

```
        世界 Boss
            │
 ┌──────────┼──────────┐
 │          │          │
 QQ群 A    QQ群 B     QQ群 C
 玩家      玩家       玩家
 │          │          │
 └──────────┼──────────┘
            ↓
       全局贡献统计
            ↓
     奖励池 / 排名 / MVP
```

核心机制包括：

- 全局共享 Boss
- 玩家贡献统计
- 贡献排行
- MVP
- 最后一击
- 共享奖励池
- 个人奖励上限
- Boss 属性安全上限
- 狂暴机制

插件会对 Boss 的生命、攻击、防御、狂暴倍率、单次伤害及个人奖励进行运行时限制，避免后台误配置造成“无敌 Boss”或奖励经济崩坏。

# 🔐 数据与安全设计

插件的数据设计遵循几个核心原则：

### 1. 持久化

重要玩家数据不会只保存在内存中。

### 2. 经济防刷

奖励采用托管、结算、限制等机制，避免简单指令产生无限资源。

### 3. 战斗防溢出

玩家、怪物、Boss、装备、宠物等关键数据使用安全上限。

### 4. 云端数据隔离

云端内容以数据形式同步，不执行任意代码。

### 5. 本地优先

云端公开商品可以与本地商城结合，但不会无条件覆盖本地自定义商品。

### 6. 旧数据迁移

版本升级尽可能自动迁移旧数据库，不要求玩家清空存档重新开始。

# 🚀 安装与连接云端

## 1. 安装插件

将插件安装到 AstrBot 的插件目录，并重新加载 AstrBot。

## 2. 创建 YSGL 账号

进入：

**YSGL 云端玩法中心**

https://ysgl.bot.cd/astrbot

注册并进入：

**设置 → API Key**

生成完整的：

```
gw_live_...
```

API Key。

## 3. 配置插件

打开 AstrBot 插件 Web 管理页面：

```
☁️ 云端玩法
```

填写：

- 网站地址
- API Key

然后：

```
测试连接
↓
立即同步
```

即可开始使用公开云端内容。

# 🧩 技术特点

本项目基于 AstrBot 插件体系开发。

主要特点：

- Python
- AstrBot Plugin API
- SQLite
- Web 管理页面
- HTTPX 异步网络请求
- 本地持久化数据
- 云端 JSON 数据同步
- 可扩展的 RPG 数据模型

插件网络层采用异步 HTTP 客户端，云端内容通过 API 获取，不要求把网站数据库直接暴露给 AstrBot。

# 💡 设计理念

群聊世界最重要的不是“有多少条指令”。

而是：

> **让玩家的每一次选择，都能成为这个世界的一部分。**

你今天探索得到的材料，可以用于明天制作装备。

你今天培养的角色，可以参加下周的世界 Boss。

你所在的 QQ 群，可以成为整个世界地图中的一座城镇。

你在一个群里发布的悬赏，可以让另一个群的玩家前来挑战。

而世界 Boss 的战绩，则会成为所有群共同的历史。

这就是：

# 🌌 群聊世界

**一个 QQ 群，一个地区。**

**一群玩家，一个世界。**

**每一次冒险，都留下属于你的记录。**
